Ansvisor ships a [Model Context Protocol](https://modelcontextprotocol.io)
server at `https://app.ansvisor.com/api/mcp` (or your own host if you
self-host) so AI assistants can query your brand visibility data through
natural-language conversation. No npm package, no local process — just a URL
and an API key.

## Generate an API key

1. Open your Ansvisor dashboard → **Settings** → **API Keys**
2. Click **New key**, give it a memorable name (e.g. _Claude — laptop_)
3. Copy the token. It's shown **once** — store it in your password manager

The dialog that shows the key also has a ready-to-paste setup for each client
below, with the key filled in. The snippets on this page read the key from an
environment variable instead, so it stays out of your config files:

```bash
export ANSVISOR_TOKEN=ans_...
```

Every client connects to the same URL with the same header:
`Authorization: Bearer <your key>`. There is no OAuth sign-in.

## Connect your client

### Claude Code

```bash
claude mcp add --transport http ansvisor https://app.ansvisor.com/api/mcp \
  --header "Authorization: Bearer ${ANSVISOR_TOKEN}"
```

### Claude Desktop

Claude Desktop adds remote servers as **custom connectors**. The
`claude_desktop_config.json` file only starts local servers, so a `url` entry
there is ignored.

1. Open **Settings → Connectors** and choose **Add custom connector**
2. Name it _Ansvisor_ and enter `https://app.ansvisor.com/api/mcp` as the URL
3. Under authentication choose **No sign in**
4. Under **Request headers**, add `Authorization` with the value `Bearer ans_...`

On Team and Enterprise plans, an owner adds the connector under
**Organization settings → Connectors** first.

### Codex CLI

```bash
codex mcp add ansvisor --url https://app.ansvisor.com/api/mcp \
  --bearer-token-env-var ANSVISOR_TOKEN
```

Or add it to `~/.codex/config.toml`:

```toml
[mcp_servers.ansvisor]
url = "https://app.ansvisor.com/api/mcp"
bearer_token_env_var = "ANSVISOR_TOKEN"
```

### Cursor

Add to `~/.cursor/mcp.json` (all projects) or `.cursor/mcp.json` (one project):

```json
{
  "mcpServers": {
    "ansvisor": {
      "url": "https://app.ansvisor.com/api/mcp",
      "headers": { "Authorization": "Bearer ${env:ANSVISOR_TOKEN}" }
    }
  }
}
```

### VS Code

Add to `.vscode/mcp.json`, or run **MCP: Open User Configuration** from the
Command Palette to add it for every workspace. VS Code asks for the key the
first time it connects:

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "ansvisor-token",
      "description": "Ansvisor API key",
      "password": true
    }
  ],
  "servers": {
    "ansvisor": {
      "type": "http",
      "url": "https://app.ansvisor.com/api/mcp",
      "headers": { "Authorization": "Bearer ${input:ansvisor-token}" }
    }
  }
}
```

### Windsurf

In the Cascade panel, open **… → Open MCP config file** and add:

```json
{
  "mcpServers": {
    "ansvisor": {
      "serverUrl": "https://app.ansvisor.com/api/mcp",
      "headers": { "Authorization": "Bearer ${env:ANSVISOR_TOKEN}" }
    }
  }
}
```

### Gemini CLI

```bash
gemini mcp add --transport http \
  --header "Authorization: Bearer ${ANSVISOR_TOKEN}" \
  ansvisor https://app.ansvisor.com/api/mcp
```

This writes the server to `~/.gemini/settings.json` with `httpUrl`. Use
`httpUrl`, not `url`, if you edit the file by hand: `url` means the older SSE
transport.

### Hermes Agent

Add to `~/.hermes/config.yaml`. Hermes reads `ANSVISOR_TOKEN` from your
environment or from `~/.hermes/.env`:

```yaml
mcp_servers:
  ansvisor:
    url: "https://app.ansvisor.com/api/mcp"
    headers:
      Authorization: "Bearer ${ANSVISOR_TOKEN}"
```

### OpenClaw

Add to `~/.openclaw/openclaw.json`:

```json
{
  "mcp": {
    "servers": {
      "ansvisor": {
        "url": "https://app.ansvisor.com/api/mcp",
        "transport": "streamable-http",
        "headers": { "Authorization": "Bearer ${ANSVISOR_TOKEN}" }
      }
    }
  }
}
```

Then check the connection with `openclaw mcp probe ansvisor`.

### Zed

Add to your Zed `settings.json`. Zed does not expand environment variables
here, so the key goes in directly:

```json
{
  "context_servers": {
    "ansvisor": {
      "url": "https://app.ansvisor.com/api/mcp",
      "headers": { "Authorization": "Bearer ans_..." }
    }
  }
}
```

### Other clients

Any client that supports remote MCP servers over Streamable HTTP works with
the URL and the `Authorization` header above. If yours can only start local
(stdio) servers, bridge it with [`mcp-remote`](https://github.com/geelen/mcp-remote):

```json
{
  "mcpServers": {
    "ansvisor": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote", "https://app.ansvisor.com/api/mcp",
        "--header", "Authorization:${AUTH_HEADER}",
        "--transport", "http-only"
      ],
      "env": { "AUTH_HEADER": "Bearer ans_..." }
    }
  }
}
```

Keep `Authorization:${AUTH_HEADER}` without a space, with the `Bearer ...`
value in `env`: some clients do not escape spaces inside `args`.

## Check the connection

Ask your client _"List my Ansvisor brands"_. It should call the `list_brands`
tool and show your brands. If it reports a 401, the header is missing or the
key was revoked.

## Self-host? Point at your own instance

The MCP endpoint lives at `/api/mcp` on whatever host runs the Ansvisor web
app. If you self-host at `ansvisor.mycompany.internal`, use that base URL
instead.

## Available tools

The MCP server exposes **55 tools**. Descriptions below match
[`web/src/lib/mcp/server.ts`](https://github.com/ansvisor/ansvisor/blob/main/web/src/lib/mcp/server.ts).
Tools that change data are marked **writes** — only call them on explicit user
intent, not during exploratory queries.

| `list_competitors` | Configured competitors for a brand (id, name, domain); this is not a performance ranking. | |

### Mentions & sentiment

The Mentions & Sentiment page's figures, under the page's filters: `date_from` / `date_to` (the last 30 days when left out), `platform`, `region`, `topic_id` and `search` over the prompts' text. They are built from the stored answers with no LLM call. Net sentiment runs from −100 to +100, and under 20 mentions a figure is marked `lowSample`, with no change read into it. Sentiment is measured for your brand only.

| Tool | What it does | Writes |
| --- | --- | --- |
| `get_mentions_summary` | The Overview: times named (the page's Total mentions), mentions, mention rate, prompts with mentions, average position and sentiment, now and in the window before, with each change taken on the prompts both windows answered (`changes.basis`), as the page's cards; the platform that moved net sentiment most, each platform and each day. | |
| `list_mentions` | The responses naming the brand, 100 a page, with sentiment, position, competitors in the same response and an excerpt; filter by `sentiment` or `competitor_id` (`none` for no competitor) and sort. | |
| `get_mention` | One response in full: text, citations, competitors named, sentiment and its latest correction. | |
| `get_mention_competitors` | How often AI names each competitor in the brand's responses, and how often in the same response as the brand. | |
| `get_mentions_perception` | What AI associates with the brand: its terms, the attributes that set it apart from its top competitors, co-mentions and the biggest gap. | |
| `override_mention_sentiment` | "Sentiment is wrong": correct one response's sentiment, with an optional note. The key's user must be an admin or manager. | **yes** |

The same reads are available over REST with the same `ans_` key: `GET /api/mcp/mentions/summary`, `/api/mcp/mentions`, `/api/mcp/mentions/<id>`, `/api/mcp/mentions/competitors` and `/api/mcp/mentions/perception`, with the filters as query parameters. A correction is `POST /api/mcp/mentions/<id>/sentiment-override` with `{ "sentiment": "negative", "note": "…" }`.

```bash
curl "https://app.ansvisor.com/api/mcp/mentions/summary?brand_id=<brand_id>&platform=gemini-web" \
  -H "Authorization: Bearer ans_..."
```

### Content Editor

Drafts are read and written as a person would in the editor. Ansvisor never publishes, and a suggestion isn't applied until a person accepts it. None of these tools calls an LLM: the assistant writes the drafts and suggestions itself.

The MCP never sends a page to a CMS: Ansvisor's own **Send to CMS** stays in the product. To publish from your assistant, put the page on your CMS with the assistant's own CMS connector, then call `mark_content_draft_published` with the address it went live at, so Ansvisor measures it. Over REST: `GET /api/mcp/content-plan?brand_id=<brand_id>&days=30` and `POST /api/mcp/content-drafts/<id>/published` with `{ "url": "…" }`.

| Tool | What it does | Writes |
| --- | --- | --- |
| `list_content_drafts` | The brand's drafts, latest changed first (up to 100), with status, method (`create` or `optimize`), author, open suggestions and the editor path; filter by `status`. Each says where it was last sent (`last_send`: status, target, when, the error, where it went live) and whether its shopping links still sell (`shopping_links`). | |
| `get_content_draft` | One draft: its HTML, its numbered passages (`locked` ones AI answers quote today), where and since when the page is live, its Action Center action, the open suggestions and the only pages a suggestion may link to; with `last_send`, `shopping_links` and, on an online shop's page, its `shopping_path` (the category pages and products it should link). | |
| `get_content_sources` | What the draft draws on over 30 days, as the Sources tab shows it: prompts, AI searches (fan-outs), cited pages, Search Console queries and the person's choices. | |
| `get_content_impact` | What the draft's live page earns (citations, AI visits, Google clicks, the prompts citing it) against the period before, as the Live page tab reads it. Only for a draft of a live page. | |
| `create_content_draft` | Write a new draft as the agent (`create`, or `optimize` a page on the brand's domains); it goes to the Library's In review. | **yes** |
| `add_content_source` | Add a prompt, a cited page or a Search Console query to the draft's sources. | **yes** |
| `suggest_content_changes` | Leave up to 20 suggestions (replace or insert, each with a reason) for a person to accept or reject. Refused on a published draft, while open suggestions wait, or while the Content Agent writes it. | **yes** |
| `mark_content_draft_published` | Mark a draft Published at the address it went live at, as the editor's **Mark published** does, once your own CMS connector has put it there. Ansvisor then measures that address, and a linked action's Publish task completes. | **yes** |
| `set_content_draft_ready` | Set a draft ready, as the editor's Mark ready does, without its Before you publish check; a linked action's writing task completes once every page it names has a ready draft. A draft in review waits for a person. | **yes** |

#### Export an action

`get_action` takes an optional `format`:

- `json` (default): the fields above.
- `markdown`: everything the action's tabs show, ready to paste into a doc, a ticket or another agent. This is the same text as **Copy Data** in the dashboard.
- `csv`: a row per affected item, task and signal, with a `section` column. This is the same file as **Export CSV**.

Labels are in English and dates in UTC. The same export is available over REST with the same `ans_` key. The CSV comes as a download (`action-AC-52.csv`) that Excel opens as UTF-8.

```bash
curl "https://app.ansvisor.com/api/mcp/actions/<action_id>?format=markdown" \
  -H "Authorization: Bearer ans_..."
```

## Try it

Ask your client things like:

- _"List my Ansvisor brands."_
- _"What's my visibility score on ChatGPT for the last 7 days?"_
- _"Are my topics balanced?" / "Which topic has the most prompts?"_
- _"Show me the prompts in my pricing topic."_
- _"Who are my top 5 competitors by mention count this month?"_
- _"Why did our sentiment drop on Gemini?"_

The model picks the right tool, fills in the brand id and filters, and
answers in plain English using the returned data.

## When the plan has ended

On Ansvisor Cloud, a workspace without an active plan is read-only (see
[What happens when my plan ends?](/faq)). Its API keys keep working for
reading:

- `list_` and `get_` tools run as usual.
- Every other tool (each one marked **writes** above) is refused before it
  runs. The call fails with this text:

  ```json
  {
    "error": "plan_limit",
    "code": "subscription_inactive",
    "message": "This workspace's plan isn't active (its free trial ended or it was canceled), so it is read-only: reading still works, but nothing can be changed, run or generated until an admin chooses a plan in Settings › Billing."
  }
  ```

- The REST routes under `/api/mcp/…` answer a `POST`, `PUT`, `PATCH` or
  `DELETE` with `402` and the same body.

Retrying doesn't help: an admin has to choose a plan first. New API keys
can still be created; on a read-only workspace they only read. A self-hosted
instance is never read-only.

## Revoking access

If a key leaks or you stop using a client, open **Settings → API Keys** and
click the trash icon. Clients using that key lose access immediately.

## Transport

The server speaks the
[MCP Streamable HTTP](https://modelcontextprotocol.io/specification/2025-03-26/basic/transports#streamable-http)
transport in stateless mode — every request is self-contained, no session
state is kept between calls. This makes it work cleanly behind any HTTP
load balancer and on serverless runtimes.
