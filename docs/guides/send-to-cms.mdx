---
title: "Send to CMS"
description: "Send Content Editor pages to Webflow as draft items, or to your CMS through your workflow tool, and see where they went."
---

**Send to CMS** sends a Content Editor page to your CMS in one of two ways:

- **Webflow:** the page goes straight into a collection of your brand's Webflow site as a **draft item**. You publish it in Webflow.
- **Your workflow:** the page goes to your brand's webhook as a content package (the page ready to publish, its title, slug, meta title, meta description, author and featured image). Your workflow tool (n8n, Make, Zapier or your own endpoint) turns it into a post or page in your CMS, and decides whether it lands as a draft or goes live.

Ansvisor never publishes on its own. When your workflow tells Ansvisor where the page went live, or once you publish the item in Webflow, the draft becomes **Published** and its address shows in the Library.

## Connect Webflow

1. Get a site token in Webflow, as the **Webflow** card's steps say:
   1. Go to **Site settings › Apps & Integrations › API access** and click **Generate API token**.
   2. Enter a token name (4–80 characters), for example "Ansvisor connector".
   3. Under **Permissions**, set **CMS** to **Read and write** and **Sites** to **Read-only**. Leave everything else on **No access**.
   4. Click **Generate token** and copy the token. Webflow shows it only once.
2. In Ansvisor, open **Settings → Integrations** with the brand selected, and paste the token in the **Webflow** card. It's checked with Webflow and kept by our connector service. It's never shown again, and Ansvisor's database doesn't hold it. Only **admins and managers** can connect Webflow, pick the collection, replace the token or disconnect; members see where the brand's pages go.
3. Pick the **collection** your pages go to (your blog's, for example), then which of its fields takes what:

   | Part of the page | Webflow field type | |
   |---|---|---|
   | Page content | Rich text | Required |
   | Meta title | Plain text | Optional |
   | Meta description | Plain text | Optional |
   | JSON-LD (structured data) | Plain text | Optional |
   | Date (the day it's first sent) | Date/Time | Optional |

   The page's title and slug always go to the item's **Name** and **Slug**. Ansvisor suggests fields from their names (`post-body`, `post-summary`, `seo-title`…); change them if they're wrong, and **Save**. A collection that requires a field Ansvisor doesn't fill can't be saved: **Save** names the field. Make it optional in Webflow first. A page sent again keeps its item's date; an item that has none (sent before you mapped a date field) gets the day it's sent again.
4. To use the JSON-LD field, add an **Embed** to the collection template that puts the field inside a `<script type="application/ld+json">` tag.

A site token is one site's, so each brand connects its own. **Replace token** changes it (the collection and fields stay when it's the same site), and **Disconnect** removes it. If Webflow refuses the saved token, the card says so and asks for a new one.

<Note>
**Self-hosting:** Webflow goes through Composio. Set `COMPOSIO_API_KEY` and `COMPOSIO_WEBFLOW_AUTH_CONFIG_ID` (a Composio auth config of the Webflow toolkit with API-key auth) on the API server. Without them, the card says Webflow isn't set up, and pages go to your workflow only.
</Note>

## Set up your workflow

1. Open **Content → Opportunities → Webhook Settings**.
2. Enter your workflow's webhook URL.
3. Set a **Secret key**. Ansvisor sends it with every request, signs each page with it, and your workflow needs it to report where a page went live.
4. Tick **Content page sent**. It is off by default, so a workflow built for opportunities doesn't receive pages it doesn't expect.
5. Save.

Only **admins and managers** can send pages.

## Choose where pages go

Once the brand's Webflow collection is ready, the Send dialog offers **Webflow** (first) or **Your workflow**. Your choice, and where you last sent, is remembered for the brand in your browser. If Webflow is connected but not ready (its token refused, or no collection picked), it shows but can't be picked, with what to fix, so a page doesn't go to your workflow unnoticed. If the dialog can't check Webflow just then, the page goes to your workflow; if you chose Webflow before, the dialog says so, with **Try again**.

## Send one page

- **From the editor:** click the paper-plane icon in the header. **Before you publish** opens first only when it has something to ask about: Trust under 60, something missing (an author, placeholders, alt text, broken links) or checks still being read. Check it and click **Continue to send**. Its JSON-LD is folded away here; **Show the JSON-LD** opens it for a CMS that doesn't add one.
- **From the Library:** open a row's **…** menu and pick **Send to CMS**.

The dialog fills the fields from the page, and you can change them before sending:

| Field | Filled from |
|---|---|
| **Slug** | The live page's address for an optimized page, else the title: without a leading "the" or "a", cut at a word near 60 characters, never ending on a word such as "to" or "across". Letters, digits, dots, `-` and `_`, up to 200 characters. |
| **Meta title** | The title. A long one gives its first part when it has one ("AEO tools compared side by side for marketing teams: a 2026 guide to the best" gives "AEO tools compared side by side for marketing teams") and that says enough, else it's cut at a word near 60 characters, never ending on a word such as "to" or "across". |
| **Meta description** | The page's first paragraph. |

The slug and meta you send are kept on the draft, so the next send starts from them.

**To Webflow**, the page becomes a draft item in the collection. Sending it again **updates** the same item (a new one is made if it was deleted in Webflow, or after you switch collections); a live item's changes wait for your next publish in Webflow. The item's slug is the page's slug in the form Webflow takes: lowercase letters, digits, `-` and `_`, with accents dropped and dots turned into `-`, so the live address can differ slightly from the slug in the dialog. Webflow's rich text has no tables and Ansvisor doesn't upload images yet, so:

- a table goes as a list, one item a row ("Header: cell · …");
- images aren't sent: add them in Webflow;
- a meta description left empty goes as the page's opening words.

The toast says whether the item was made or updated, and what changed on the way.

Once you publish it in Webflow, the page becomes **Published** at its address on your site: `/{collection}/{slug}` on the custom domain the site was last published to, or on its `webflow.io` address when it has none. Ansvisor checks when you open the Library and once a day, for sends from the last 60 days. A page published in Webflow later than that stays "In Webflow as a draft item"; sending it again starts the check over. A page sent again stays sent until Webflow publishes it again, and a page whose item you deleted in Webflow reads "Removed in Webflow"; send it again to make a new item.

The page goes as **Export** makes it: the HTML without its H1 (your CMS's title field carries it), with the byline line if your brand adds the byline to its content. Ansvisor holds the send while:

- a placeholder such as `[figure, source]` is still open: **Fill now** selects the first one, in the page or, when it's in an image's alt text, the JSON-LD or an HTML block, in the HTML view. The editor's toolbar counts those left and steps through them;
- the page has no title, or nothing under its title;
- the slug can't be used.

## Send several pages

In the **Library**, tick the rows to send (up to 25 at once) and click **Send to CMS** in the bar above the table. The dialog lists each page as **Ready**, or says why it can't go. A page that can't go is left out; fix it in the editor. Each page goes with the slug and meta of its last send, or the page's own.

The pages are sent one after another in the background, with a short pause between them so your CMS isn't flooded. The dialog follows them and says how many went, and you can close it at any time: the Library keeps following them. Very long pages go in more than one request, each once the one before has gone; closing the dialog while one waits stops the rest, and it says how many didn't go.

A workspace can send **200 pages in 24 hours**, to Webflow and to your workflow together. A page already on its way to Webflow can't be sent there again until it has gone.

## See how a send went

Beside each row's status, the Library shows its last send:

| Icon | Meaning |
|---|---|
| Clock | On its way. |
| Paper plane | Your workflow took it (it answered with a 2xx status), or it's a draft item in Webflow. |
| Red warning | It failed. Hover it to see what your workflow answered or reported, or why it couldn't be reached. |
| Blue link | Published. Click it to open the live page. |

To list only some of them, use the **Last send** filter beside **Created**: **Never sent**, **Sending**, **Sent**, **Failed** or **Published**. It shows once a page of the brand has been sent. The filter is kept in the page's address (for example `?sent=failed`), and **Export** exports the rows it lists.

## Build the workflow

Every workflow has the same three steps:

1. **Receive** the `content_draft.sent` package with a webhook trigger. Check the `X-Webhook-Secret` header, or the `X-Ansvisor-Signature` header, against your secret.
2. **Create** the post in your CMS from `page`, for example:

   | CMS field | Package field |
   |---|---|
   | Title | `page.title` |
   | Body / content | `page.html` |
   | Slug | `page.slug` |
   | SEO title | `page.metaTitle` |
   | SEO / meta description | `page.metaDescription` |
   | Author | `page.author` |
   | Featured image | `page.featuredImage.src` (alt text in `page.featuredImage.alt`) |
   | Schema / head code | `page.jsonLd` |

   Create it as a **draft** if someone should review it in the CMS first. When `page.method` is `optimize`, the page was made from the live page at `page.sourceUrl`: update that post instead of creating a new one.
3. **Report** how it went: when the post is published, send `POST` to the package's `callback_url` with `{ "status": "published", "url": "https://www.example.com/blog/pour-over" }` and your secret in the `X-Webhook-Secret` header. If your CMS refused it, send `{ "status": "failed", "reason": "…" }` instead.

   If the post is published later, run this step from your CMS's "post published" trigger. Keep the package's `delivery.id`, or the `callback_url` itself, with the post so the trigger can find it.

Answer the webhook quickly, within 15 seconds, and do slow work afterwards. Ansvisor sends each page once and doesn't retry, so a failed send is sent again from the Library.

<Tip>
**n8n:** Webhook node → your CMS node (WordPress, Webflow, Ghost…) or an HTTP Request node → HTTP Request node to `{{$json.body.callback_url}}`.

**Make:** Custom webhook → your CMS module → HTTP "Make a request" module to the callback URL.

**Zapier:** Webhooks by Zapier "Catch Hook" → your CMS action → Webhooks by Zapier "POST" to the callback URL.
</Tip>

The package's fields, the signature and the callback are described in [Webhooks](/api-reference/webhooks).
