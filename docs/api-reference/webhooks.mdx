## Configuration

Each brand has one webhook, set up in **Content → Configure Webhook**:

- **Webhook URL** — your endpoint. Ansvisor sends `POST` requests with a JSON body.
- **Secret key** (optional) — sent back to you in a header on every request, so your endpoint can tell that the call came from Ansvisor.
- **Active** — pause delivery without deleting the webhook.

The webhook receives every event below. Check the `event` field to tell them apart.

## Events

| Event | Sent when |
|---|---|
| `opportunity.sent` | A user sends a content opportunity to the workflow — from the opportunity page, or several at once from the opportunities list |
| `daily_pulse.created` | A brand's Daily Pulse is generated (on cloud and self-host alike) |
| `webhook.test` | **Test Webhook** is pressed in the webhook settings |

## Verifying requests

When a secret key is set, every request carries it unchanged in a header:

```
Content-Type: application/json
X-Webhook-Secret: <your secret key>
```

Compare it with the secret you configured and reject the request on a mismatch. Use a constant-time comparison:

```js
import crypto from 'crypto';

function isFromAnsvisor(req, secret) {
  const received = Buffer.from(req.headers['x-webhook-secret'] ?? '');
  const expected = Buffer.from(secret);
  return received.length === expected.length && crypto.timingSafeEqual(received, expected);
}
```

The secret travels in the request itself, so only use an `https://` endpoint.

## Event payloads

Payloads are flat JSON objects with an `event` field at the top level.

### `opportunity.sent`

```json
{
  "event": "opportunity.sent",
  "opportunity": {
    "id": "uuid",
    "title": "Publish a comparison page for project management tools",
    "description": "Competitors are cited for this prompt and you are not.",
    "type": "owned",
    "impact": "high",
    "opportunity_score": 82.5
  },
  "prompt": { "text": "best project management tools for agencies", "category": "comparison" },
  "data": {
    "promptText": "best project management tools for agencies",
    "visibilityScore": 12,
    "competitorGap": 45,
    "competitorsCited": ["Competitor A", "Competitor B"]
  },
  "brief": {
    "suggestedTitle": "…",
    "contentType": "comparison-page",
    "targetWordCount": 2000,
    "outline": [{ "heading": "…", "keyPoints": ["…"] }],
    "targetKeywords": ["…"],
    "competitorInsights": "…",
    "callToAction": "…"
  },
  "brand": { "name": "Acme", "domain": "acme.example", "industry": "Software" },
  "callback_url": "https://api.example.com/api/content/<opportunity id>/status"
}
```

- `prompt` is `null` when the opportunity is not tied to a prompt.
- `data` is the evidence behind the opportunity; its fields depend on the opportunity type.
- `brief` is `null` until a content brief has been generated for the opportunity.
- `callback_url` points at `PATCH /api/content/{id}/status`, which takes `{ "status": "in_progress" }` (or `new`, `sent`, `done`, `dismissed`). The endpoint authenticates with a dashboard user's access token — see [Authentication](/api-reference/authentication#bearer-token) — not with the webhook secret.

Once your endpoint responds, the opportunity is marked `sent` whatever status code you return, and that status code and the first 1,000 characters of your response body are stored on it. If the request times out or the connection fails, the opportunity keeps its previous status.

### `daily_pulse.created`

```json
{
  "event": "daily_pulse.created",
  "brand": { "id": "uuid", "name": "Acme" },
  "pulse": {
    "date": "2026-07-30",
    "frequency": "daily",
    "kpis": {
      "visibilityRate": 42.5,
      "visiblePrompts": 17,
      "promptCount": 40,
      "weekRate": 44.1,
      "prevWeekRate": 45.3,
      "weekTrend": -1.2,
      "mentions": 31,
      "mentionsChange": 4,
      "citations": 12,
      "citationsChange": -2,
      "sentimentPct": 68,
      "sentimentChange": 3,
      "totalResults": 120
    },
    "highlights": [
      { "type": "first_citation", "key": "first_citation:https://acme.example/guide", "url": "https://acme.example/guide", "label": "…", "promptText": "…" }
    ],
    "warnings": [
      { "type": "competitor_surge", "key": "competitor_surge:<id>", "competitorName": "…", "from": 20, "to": 31 }
    ],
    "degraded_platforms": [],
    "insights_url": "https://app.example.com/dashboard/insights"
  }
}
```

`frequency` is the brand's pulse setting (`daily`, `weekly` or `notable`); no pulse is generated when it is `off`. See the [Daily Pulse guide](/guides/daily-pulse) for when a pulse is sent and what each highlight and warning means.

Highlight types and their fields:

| `type` | Fields |
|---|---|
| `first_citation` | `url`, `label`, `promptText` |
| `prompt_gain` | `promptText`, `gain` |
| `competitor_overtaken` | `competitorName`, `brandRate`, `competitorRate` |
| `new_engine` | `platform` |

Warning types and their fields:

| `type` | Fields |
|---|---|
| `sharp_drop`, `visibility_slipping` | `from`, `to`, `drop` |
| `competitor_surge` | `competitorName`, `from`, `to` |
| `competitor_crossed` | `competitorName`, `competitorRate`, `brandRate` |
| `lost_citations` | `promptText` |

Every highlight and warning also has a `key` that identifies its subject.

### `webhook.test`

```json
{
  "event": "webhook.test",
  "message": "This is a test webhook from AEO platform.",
  "timestamp": "2026-07-30T10:00:00.000Z"
}
```

The test uses the URL and secret currently in the form, so you can check an endpoint before saving it.

## Delivery

- Each event is sent **once**. There are no automatic retries.
- Ansvisor waits up to 15 seconds for a response (10 seconds for `webhook.test`).
- Respond with a 2xx status quickly and do slow work after responding.
